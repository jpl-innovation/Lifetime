# 1.3.0 diagnostics: text for the real docs

Worker 2 (diagnostics). The lead merges this into README.md, RELEASE_NOTES.md ("Next release"), SECURITY.md and
docs/SERVER_OPERATIONS.md. Plain words, as the user sees them.

## RELEASE_NOTES.md, "Next release"

- **Diagnose connection** (desktop, Connect page). On the code step, and when the computer is connected or the
  server is offline, press **Diagnose connection**. Each check gets one line with a state (Passed, Check,
  Problem, Info, Skipped) and plain words. Every line marked Check or Problem says what to do next. The checks:
  - which address is checked: the typed connection line, the saved connection, or "searching the network" when
    only a code was typed;
  - whether the server name resolves on this network;
  - whether the server port (8443, or the port in the line) answers, and if not, whether the cause is a refusal
    (Lifetime Server is not running there), no answer (server off or firewall) or no network path;
  - whether a Lifetime Server answered the network search on port 5353, with its name and address. When only a
    code was typed and several servers answered, the one whose certificate matches the code is checked (up to
    four are tried, as Connect does). If none matches, the line says that several servers answered;
  - which local networks the network search covers, and the Ubuntu case where the computer's name points to
    127.0.1.1 (handled);
  - whether the server's certificate names the address, whether it matches the typed code, and its dates;
  - the clock difference from the server (only after the certificate matched the typed code);
  - on Windows, the network profile. A Public network matters only when this computer is the server, and the
    line says so.
  **Copy report** copies the lines as plain text. A code in it shows as LTS-****.
- **Self check** (server, Administration). **Run self check** lists the address the server listens on, the
  address computers are told to use and whether it resolves, whether the certificate names that address and the
  server's own IP, whether discovery is running (and why not), the firewall, the server time and certificate
  expiry. Each problem line says what to do. Self check finishes within 8 seconds: a name lookup gets 2 seconds,
  and the firewall gets the time that is left. Anything it could not read in time says so. Only one Self check runs
  at a time, and its result is reused for 30 seconds.
  - Windows: whether the LifetimeServer-Connect firewall rule exists, is on and allows the server's port, and
    whether any network is Public.
  - Linux: whether ufw or firewalld is on and allows the server port (tcp) and 5353/udp. ufw: the default
    incoming policy, Anywhere rules, port ranges and lists (`ufw status verbose`). firewalld: every active zone
    (or the default zone), ACCEPT targets, port ranges, services and rich rules (`--list-all-zones`). A rule that
    is not seen is reported as Check, never Problem, because rule order and other tools can change the answer.
    That line gives the command to verify and the command to fix. When the rules cannot be read without
    administrator rights, the line says which command to run. Nothing is ever changed.
  - Also from the command line: `LifetimeServerRuntime admin --directory <data> --operation self_check`
    (source installs: `python lifetime_server.py admin ...`). The JSON has a `message` and `what_to_do` in
    English for each line.
- **Copy diagnostics** in both apps (desktop: Connect page; server: Administration > Self check). It copies
  the version, the system, settings that are not secret, the reporting service's state and last problem, the last
  Diagnose connection or Self check, the last server log events, and the last 200 lines of the app's own log when
  it has one and it can be read. Left out: the computer's identity fields and the names of computers in the
  server log. The text is scrubbed of what is listed under SECURITY.md below.

## SECURITY.md

- Diagnose connection does not weaken pinning or the code check. Before the certificate has matched the typed
  code it uses only a name lookup, TCP connects, one discovery query, and TLS handshakes that read the certificate
  and send no application data. Then it may send one empty `HEAD /` to read the server's `Date` header. The server
  refuses that request and it carries nothing. For a saved connection no request is sent, because the pinned
  certificate is in the administrators-only database.
- Self check is a read operation. Every role that can read (Viewer and up) may run it, and the audit trail
  treats it like the other reads. It runs only fixed read-only commands (Get-NetFirewallRule,
  Get-NetConnectionProfile, systemctl is-active, ufw status verbose, firewall-cmd --list-all-zones). Nothing typed
  by a person goes into them. PowerShell output is read as UTF-8. It never reports the administration port. Only
  one run at a time, reused for 30 seconds, so a reader cannot start a stream of PowerShell processes.
- Names from discovery answers are untrusted. Before they appear in Diagnose connection or a copied report, control
  characters and new lines are removed and the names are cut to 63 characters.
- Copy diagnostics copies only named fields, and then scrubs the text. Exactly what is masked:
  - Connection codes, upper or lower case, with O/I/L for 0/1/1. Masked shapes: five groups of four characters
    with one kind of separator (spaces, tabs, new lines, dots, dashes or underscores, 1-4 of them), or 20
    characters in a row. With an LTS prefix the code is always masked; without it, only when its check character is
    right. Also masked: LTS followed by 4-20 code characters (a partial code).
  - Enrollment bundles (`lifetime-enrollment-v1:...`) and `Bearer` values.
  - The value after a key whose name contains token, pass, passw..., pwd, secret, credential, serial, webhook,
    api key, authorization or username (for example "Serial Number", "smtp_pass"). The key may be followed by `:`,
    `=` or " is ". The value may be a word, a quoted string, a JSON string with escaped quotes, or double-escaped
    JSON. When the key ends a line, the value on the next line is masked too.
  - In URLs: the user name and password (`scheme://user:pass@`), and everything after the host (path, query,
    fragment). That covers webhooks.
  - Long random tokens of 32 or more letters, digits, `_` or `-`. SHA-256 fingerprints (64 hex characters) and
    device IDs (UUIDs) are kept.
  - The user name in home folder paths (`C:\Users\<name>\`, `/home/<name>/`).
  - Lines longer than 4000 characters are cut, never leaving part of a token behind. This keeps scrubbing fast
    (256 KB in well under a second).
  - Not masked: anything else, for example a secret written as free text with no key in front of it, or a short
    token below 32 characters with no key in front of it.
  A test plants a secret in every source, including fields the allow-lists keep, and checks that none is copied.

## docs/SERVER_OPERATIONS.md

- New admin operation `self_check` (read, Viewer and up): `{checks: [{state, text, fix, values, message,
  what_to_do}], checked_at}`. `state` is good, warning, danger, info or neutral.
- The dashboard needs a 1.3.0 server for Self check. Only when the server does not know the operation (HTTP 404)
  does it say "Update Lifetime Server". A timeout, a missing role and other failures each get their own words.
  Copy diagnostics needs only `server_info` and `server_log`, so it also works with an older server.

## Not verified on real machines

These were tested only with unit tests: a loopback server, and mocked discovery, PowerShell, systemctl, ufw and
firewall-cmd. They still need checking on real machines:
- Diagnose connection against a real LAN server: discovery answers, a name that does not resolve, a blocked port,
  a Public network on the server PC.
- Self check on a real Windows Server (rule present, missing or on another port; Public profile) and on Ubuntu
  with ufw on, and on a distribution with firewalld on. The server runs as the `lifetime` user there, so ufw is
  expected to say "only an administrator can read its rules". Whether `firewall-cmd --list-all-zones` works without
  root depends on the distribution's polkit rules. The ufw and firewalld output formats were taken from their
  documentation and tested only with samples.
- A network name that is not ASCII ("WLAN (Büro)") was tested with a fake PowerShell, not with a real adapter.
- The desktop setup log (`install.log` in the agent data folder) is for administrators only. Copy diagnostics
  usually copies only the `%TEMP%\LifetimeAgent-install.log` copy, when one exists. On Linux the desktop has no log
  file of its own (the agent logs to the systemd journal), so none is included. The Linux server's
  `/var/log/lifetime-server.log` is included only when that file exists and the dashboard's user can read it.
  The systemd service logs to the journal, so this file is usually missing.
